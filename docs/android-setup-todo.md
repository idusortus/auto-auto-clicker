## Path A — User-space toolchain (NO sudo) ✅ verified path

Everything lands under `$HOME`; nothing touches `/usr`. This avoids the system 32-bit libraries
(`lib32z1 lib32stdc++6 libc6:i386`) that the Android SDK's native tools historically needed on a
**system/`apt` install** (Path B) — see Step B4.

### A1. Install a user-space JDK 17 (Temurin/Adoptium archive)

Ubuntu 26.04 may not package `openjdk-17-jdk` (newer releases sometimes ship only JDK 21+ or move
to `default-jdk`). The user-space archive sidesteps that risk entirely.

```bash
# Resolve the current Temurin 17 Linux x64 tarball URL from the Adoptium API
curl -sS "https://api.adoptium.net/v3/assets/latest/17/hotspot?architecture=x64&image_type=jdk&os=linux&vendor=eclipse" \
  -o /tmp/temurin17.json
python3 -c "import json;print(json.load(open('/tmp/temurin17.json'))[0]['binary']['package']['link'])"

# Download into $HOME (URL below was current on 2026-10-03; use the URL printed above if it moved)
mkdir -p "$HOME/jdk17-download"
curl -fSL -o "$HOME/jdk17-download/temurin17.tar.gz" \
  "https://github.com/adoptium/temurin17-binaries/releases/download/jdk-17.0.20.1%2B1/OpenJDK17U-jdk_x64_linux_hotspot_17.0.20.1_1.tar.gz"

# Extract to $HOME/jdk-17
mkdir -p "$HOME/jdk-17"
tar -xzf "$HOME/jdk17-download/temurin17.tar.gz" -C "$HOME/jdk-17" --strip-components=1
"$HOME/jdk-17/bin/java" -version    # expect: openjdk version "17.0.x"
```

> **Note (Ubuntu 26.04 JDK risk):** if you prefer the distro JDK on Path B and
> `apt-get install openjdk-17-jdk` reports "no installation candidate", install **any** JDK 17+
> the distro ships and point Gradle at it explicitly with
> `org.gradle.java.home=/path/to/jdk-17` in `mobile/android/gradle.properties` (that file is
> regenerated by prebuild; see the reference repo's approach in `docs/setup.md`). Preferring the
> Temurin archive avoids the whole question.

### A2. Install Android `cmdline-tools` under `$HOME` (no sudo)

```bash
mkdir -p "$HOME/android-sdk/cmdline-tools"
curl -fSL -o /tmp/cmdline-tools.zip \
  "https://dl.google.com/android/repository/commandlinetools-linux-13114758_latest.zip"
unzip -q -o /tmp/cmdline-tools.zip -d "$HOME/android-sdk/cmdline-tools"
# sdkmanager REQUIRES the directory be named "latest":
mv "$HOME/android-sdk/cmdline-tools/cmdline-tools" "$HOME/android-sdk/cmdline-tools/latest"
ls "$HOME/android-sdk/cmdline-tools/latest/bin"   # sdkmanager, avdmanager, ...
```

> **Important:** `sdkmanager` fails with "Could not determine SDK root" unless the tools live in
> `cmdline-tools/latest/`. The rename step above is mandatory.

### A3. Accept licenses and install SDK components (non-interactive)

```bash
export JAVA_HOME="$HOME/jdk-17"
export ANDROID_HOME="$HOME/android-sdk"
export ANDROID_SDK_ROOT="$HOME/android-sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

yes | sdkmanager --licenses
yes | sdkmanager --install "platforms;android-36" "build-tools;36.0.0" "platform-tools"
sdkmanager --list_installed   # expect all three rows below
```

Expected `--list_installed` (verified on this host):

```
  build-tools;36.0.0   | 36.0.0  | Android SDK Build-Tools 36 | build-tools/36.0.0
  platform-tools       | 37.0.1  | Android SDK Platform-Tools | platform-tools
  platforms;android-36 | 2       | Android SDK Platform 36    | platforms/android-36
```

> **No `sudo`, no 32-bit libs.** On this host `ldd` reports **all libraries resolved** for both
> `aapt2` and `adb` on the user-space install — the `lib32z1`/`libc6:i386` packages are a
> Path B (system install) concern only, not a requirement here.

### A4. Persist the environment (`~/.bashrc` snippet)

Append this to `~/.bashrc` so every new shell has the toolchain (adjust the paths if you installed
elsewhere):

```bash
# >>> Android build toolchain (auto-auto-clicker) >>>
export JAVA_HOME="$HOME/jdk-17"
export ANDROID_HOME="$HOME/android-sdk"
export ANDROID_SDK_ROOT="$ANDROID_HOME"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
# <<< Android build toolchain (auto-auto-clicker) <<<
```

Then `source ~/.bashrc` (or open a new shell).

## Path B — System `apt` install (needs sudo; mirrors the proven reference baseline)

Use this only where an admin password is available. It mirrors the reference repo's
`README.md` "Linux CLI Install" and `docs/setup.md`.

### B1. Base packages (JDK 17 + platform-tools)

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates gnupg git unzip openjdk-17-jdk android-sdk-platform-tools
```

> **Ubuntu 26.04 risk:** `openjdk-17-jdk` **and** `android-sdk-platform-tools` may be unavailable
> on 26.04. If so:
> - JDK: install the distro's available JDK 17+ (`apt-get install -y openjdk-17-jdk-headless` or
>   `default-jdk`) **or** use the user-space Temurin archive from Step A1 and set
>   `org.gradle.java.home` in `mobile/android/gradle.properties`.
> - `android-sdk-platform-tools`: skip the apt package entirely and get `platform-tools` via
>   `sdkmanager` (Step A3 / B3) — it is the same thing and version-current.

### B2. Android `cmdline-tools` (same as A2, but system-wide if you prefer)

```bash
sudo mkdir -p /opt/android-sdk/cmdline-tools
curl -fSL -o /tmp/cmdline-tools.zip \
  "https://dl.google.com/android/repository/commandlinetools-linux-13114758_latest.zip"
sudo unzip -q -o /tmp/cmdline-tools.zip -d /opt/android-sdk/cmdline-tools
sudo mv /opt/android-sdk/cmdline-tools/cmdline-tools /opt/android-sdk/cmdline-tools/latest
```

### B3. SDK components (same command, system SDK root)

```bash
export JAVA_HOME="/usr/lib/jvm/java-17-openjdk-amd64"   # or wherever the apt JDK landed
export ANDROID_HOME="/opt/android-sdk"
export ANDROID_SDK_ROOT="$ANDROID_HOME"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

yes | sdkmanager --licenses
yes | sdkmanager --install "platforms;android-36" "build-tools;36.0.0" "platform-tools"
sdkmanager --list_installed
```

### B4. 32-bit runtime libraries (system install only)

On a **bare Ubuntu system install**, the Android SDK's native tools (`aapt2`, `adb`) can need
32-bit runtime libraries. Install the modern equivalents:

```bash
sudo apt-get install -y lib32z1 lib32stdc++6 libc6-i386
```

(Some docs write `libc6:i386`; on amd64 Ubuntu the package name is `libc6-i386`. The user-space
Path A **does not need these** — verified with `ldd` on this host.)

## Path C — Optional EAS path (needs an Expo account + `projectId` + `EXPO_TOKEN`)

This is **not** the primary path. The primary Gradle path (A/B) needs no Expo account. Choose this
only if you already use EAS.

> **A token alone is NOT sufficient.** `eas build --local` fails without an Expo **account** and a
> **`projectId`** (`extra.eas.projectId` in `app.json`/`app.config.*`). `eas build --local` also
> does **not** read EAS dashboard environment variables — pass required values via local env.

```bash
# 1) Account + token
npx eas-cli login                       # interactive once, OR set EXPO_TOKEN below
export EXPO_TOKEN="<your Expo access token>"   # https://expo.dev/accounts/[owner]/settings/access-tokens

# 2) projectId must exist in app config (extra.eas.projectId). One-off:
npx eas-cli init                        # writes projectId into app.json

# 3) Local APK build using the repo's preview profile (mobile/eas.json, buildType: apk)
cd mobile
npx eas-cli build --platform android --profile preview --local
```

### Secrets per path

| Build path | Required secrets | Notes |
|------------|------------------|-------|
| **Gradle (A/B) — primary** | **None** | The Android SDK is installed locally (A3/B3); CI installs it in the workflow. No Expo account, no token. |
| **EAS (C) — optional** | `EXPO_TOKEN` **and** an Expo account **and** `projectId` | `EXPO_TOKEN` alone is insufficient; `projectId` must be set in app config. |
| GitHub Actions release workflow | **None for the Gradle path** | It provisions and pins the Android SDK itself. Add `EXPO_TOKEN` only if you switch the workflow to EAS. |

## Debug-keystore step (needed before the first build)

`expo prebuild` generates `mobile/android/app/debug.keystore` (and `~/.android/debug.keystore`)
automatically when absent; the release build is signed with **this debug key** for testing.

```bash
cd mobile
npx expo prebuild --platform android
# The generated keystore (gitignored — never commit it):
ls -l android/app/debug.keystore
```

Extract the SHA-1 (needed only if a service such as Google Sign-In is keyed to it):

```bash
keytool -list -v \
  -keystore android/app/debug.keystore \
  -alias androiddebugkey \
  -storepass android -keypass android \
  | grep "SHA1"
```

> **Warnings:**
> - **`expo prebuild --clean` regenerates the debug keystore with a NEW SHA-1.** Anything keyed to
>   the old key breaks. Avoid `--clean` unless a native config change requires it.
> - A release APK signed with a **different keystore cannot overwrite an existing install** —
>   testers must **uninstall first**.
> - This repo's APKs are **debug-key signed** for testing; Android will warn about an "unknown
>   developer". A stable release keystore is a deliberate follow-up, not part of this change.

## Releasing: tag → workflow → Release (see README for the full walkthrough)

The release process is documented in the project `README.md` under **"Building an Android APK
& releasing it"** (clone → build → tag → install, secrets per path, tester sideload steps). The
short version:

- **Build locally:** `npm run mobile:apk` → `mobile/dist/auto-auto-clicker.apk` (no secret).
- **Release:** push a `v*` tag → `.github/workflows/build-apk.yml` builds the APK and attaches
  it to a GitHub Release for that tag.
- **Secrets:** the Gradle path needs **none**; `EXPO_TOKEN` applies only to the optional EAS path.

### Tag strategy

- Semver with an optional pre-release suffix: `v1.4.0`, `v1.4.0-preview`, `v1.4.0-dev`,
  `v1.4.0-alpha`, `v1.4.0-beta`. Tags containing `preview`/`dev`/`alpha`/`beta` publish a
  **pre-release**.
- **Tags are immutable — bump, don't force-push.** Cut a new tag (`v0.5.1`) instead of moving
  an existing one; the Release asset and its version are keyed to the tag.
- **Only tag pushes trigger a release.** The workflow trigger is `push: tags: v*` only — no
  branch, PR, or manual trigger — so a branch push never publishes an APK.

> **CI is unverified until the first tag push actually runs it.** The local build script is the
> verified path (it produced a real APK on this host); the workflow is unproven until it runs
> green once.

## What to do if something is blocked

- **`openjdk-17-jdk` missing on Ubuntu 26.04** → use Step A1 (Temurin archive) or point Gradle at
  any JDK 17+ with `org.gradle.java.home`.
- **`android-sdk-platform-tools` missing from apt** → drop it; get `platform-tools` from
  `sdkmanager` (Step A3/B3).
- **No `sudo` at all** → the entire **Path A** works without it (verified on this host).
- **`sdkmanager` "Could not determine SDK root"** → the tools directory must be named `latest`
  (Step A2 rename).
- **Native tool `lib32` errors (`aapt2`/`adb`)** → install Step B4 packages on a system install, or
  use Path A (no 32-bit libs needed).
