## 2026-09-28 — Per-enemy curves: the roster becomes one source of truth; docs reconciled (DeepSeek V4.1 Flash)

The roster had a dual representation — descriptive per-enemy curves *plus* live `hpFactor`/`goldFactor` scaling a global canonical curve — which meant only two fields were mechanically real. The user asked for the inert fields to be made live. Rather than make both representations live (which would double-count), we collapsed to ONE source of truth: each enemy now owns its **real HP/gold curve** (`baseHp`/`hpGrowth`/`baseGold`/`goldGrowth`) and its **own boss multipliers**, and `hpFactor`/`goldFactor`/`bossStageInterval` were **deleted**. Boss cadence stays global (every 10th stage via `isBoss`); boss *size* is per-enemy. The canonical helpers left `balance.ts`; the live formula lives in `content.ts` (which already imports `balance.ts`, so the reverse would be an import cycle). `gear.gearGrowth` moved 1.283 → **1.2832**. Save schema stays **v4** — identity and max HP remain pure functions of `combat.stage`.

Deleting the cycle-mean-1 normalisation removed what had protected pacing, so a throwaway **~4,415-candidate multi-seed search** found the roster values. Result: canonical soft **6.22** / hard **55.52** min (targets 6/54 ±20%), sweep soft 5.63–6.22 / hard 50.60–55.52, all 5 seeds PASS, drops-primary 97.3–98.6%. The independent reviewer extended verification to **70 seeds, all passing**, worst margin 6.47 min above the hard floor — robust, not knife-edge.

**The key design constraint, now documented in code:** the per-enemy `hpGrowth` band must stay TIGHT (shipped: 1.4273–1.4336, a stage-50 divergence of just 1.24×), because the aggregate curve is the round-robin product of the roster's growth values — wider divergence makes the stage sequence zig-zag and drifts the pacing proof. The original descriptive metadata (1.39–1.46) diverges ~30× by stage 50, which is exactly why it never worked as authored. Distinctness lives instead in `baseHp` (24–29), `baseGold` (4–7) and the per-enemy boss multipliers.

Three defects were caught in review and fixed: an assertion had been **weakened** (`archetype` distinctness) to fit reduced data — fixed by restoring 12 distinct labels rather than the weak assertion; live source code named the wrong stages for the soft/hard check; and `decisions.md` still described the deleted factor design as live. **All documentation — human (README/STATE/NOTES) and agentic (AGENTS/decisions/histories) — was then reconciled to verified code truth**, and `AGENTS.md`'s TODO placeholders were filled with the real vision, constraints, and current shape.
