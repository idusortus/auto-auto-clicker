- 2026-09-25: Phase 1 scaffold. Node 24 / npm 12 environment; npm 12 blocks dependency install scripts by default (`npm warn install-scripts`). esbuild's blocked `postinstall` does NOT break anything — the `@esbuild/linux-x64` platform package supplies the binary and `./node_modules/.bin/esbuild --version` works. If a later phase needs an install script, run `npm install-scripts approve <pkg>`.
- 2026-09-25: `engine-core` is consumed as `.ts` source through the npm-workspace symlink. Verified cross-workspace typecheck resolution via `npx tsc -p web/tsconfig.json --traceResolution` — TS follows `exports["."].types` to `engine-core/src/index.ts`. Keep the `"types"` condition listed first in the exports map or resolution picks the wrong target.
- 2026-09-25: A side-effect import of `@auto-auto-clicker/engine-core` in `web/src/main.ts` is deliberate (Phase 1): it makes `npm run typecheck` fail loudly if workspace resolution regresses, rather than passing on an empty graph. Replace it with real imports in Phase 4.
- 2026-09-25: `engine-core/vitest.config.ts` is intentionally outside the package tsconfig `include` (["src","save","tests"]), so `tsc --noEmit` does not try to typecheck the vitest config; vitest loads it through esbuild instead.
- 2026-09-25: `PROJECT.md` and `AGENTS.md` still say "svelte and supabase" — that is stale init-template text. The authoritative stack from `decisions.md` and the phase brief is Vite + vanilla DOM + local-only (no Supabase). Do not add Svelte or Supabase.

Key structure: every formula/constant in `src/balance.ts`; `createGame`/`cloneGameState`/derived reads/`saveGame`/`loadGame` in `src/state.ts`; kill+stage-entry logic in `src/combat.ts` (draft-mutation helpers on a clone); `advance.ts` owns carry math; `actions.ts` owns command validation. `src/index.ts` re-exports constants from balance so there is no import cycle.
