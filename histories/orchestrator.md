# Orchestrator History

> Accumulated learnings about this project. Read at session start, append non-obvious discoveries.

- 2026-09-25: Ran the full build as 6 delegated phases (scaffold → engine-core+tests → sim → web renderer → mobile smoke → docs) plus one economy redesign and one targeted fix round, on a greenfield repo. Model: opencode-go/deepseek-v4.1-flash, orchestrator with coder/designer/planner/reviewer subagents.
- 2026-09-25: The planner's economy numbers were the single highest-risk artifact and were genuinely wrong — it claimed a scratch sim hit ~6.2/~52.9 min, but the real sim produced a knife-edge exponential race (player ≈1.384×/stage vs HP 1.5×/stage) that passed on one seed and missed ±20% by 30–75% on four others. Lesson: for emergent/numeric designs, do not accept a written estimate; require the implementing agent to build a throwaway parameter-search harness and a MEASURED, multi-seed acceptance criterion before the design is treated as done.
- 2026-09-25: Making the seed sweep "informational WARNING" on a core acceptance metric let a fragile result look green (`PACING OK`, exit 0) while 4/5 seeds failed. Lesson: never downgrade a primary correctness signal to a warning — either make it a hard assertion or drop it. The redesign hardened it to an all-seed assertion, which is what surfaced the true state.
- 2026-09-25: Robustness was achieved by REMOVING variance (deterministic power core, drops power-neutral after a starter weapon), which hollowed out the brief's "gear drops → upgrade gear" lever. Lesson: when a fix makes a metric robust by making an input inert, surface that trade-off to the user explicitly rather than banking the green check — robustness-by-irrelevance is still a product decision.
- 2026-09-25: Ownership-based parallelism worked cleanly with zero file conflicts: engine-core (one coder, keeps interdependent interfaces coherent) → sim → web wiring (coder), then CSS polish (designer, sequential after DOM freeze) with the Playwright smoke test (coder) run in parallel because it owned disjoint files and depended only on already-frozen testids.
- 2026-09-25: Boundary claims in docs must be test-enforced. The README/decisions asserted "engine-core has no DOM lib" while `tsconfig.json` had no `lib`, so TypeScript default-injected DOM and `document.title` typechecked inside the engine. The reviewer's probe caught it; the fix added `"lib": ["ES2022"]` plus DOM/RN-global patterns to the fs boundary test. Lesson: every "the engine cannot do X" claim needs a failing-when-violated test, not prose.
