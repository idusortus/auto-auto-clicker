- 2026-09-25: Recurring theme — docs overstate guardrails. (a) engine-core tsconfig default-injects the DOM lib despite README/decisions claiming it doesn't (probe: `document`/`window` typecheck; adding `lib:["ES2022"]` compiles clean); the boundary test does not scan for `document`/`window`/React. (b) README's 5-seed claim "stops the result from being a lucky seed" is false — all seeds are identical by construction and the sim provably cannot detect ANY loot regression (`dropChance`, `DROP_LEVEL_OFFSET`, `BAG_CAP` have zero effect on pacing). Always re-run the "would this test catch a regression?" question per subsystem.
- 2026-09-25: Unguarded tooling surfaces to watch: `sim/` has no tsconfig and is excluded from root typecheck (tsx is transpile-only; an ad-hoc `tsc --strict` was clean, but nothing enforces it), and `web/tsconfig.json` includes only `src`, so `web/tests/*` and `playwright.config.ts` are not typechecked. Also: `advance` accepts non-finite `deltaMs` and propagates NaN into `totalPlayedMs`/`damageCarry`/events; `loadGame` throws a raw TypeError on version-1 saves with a missing/null `state` (web catches it and starts fresh, so non-fatal).
- 2026-09-26: Reviewed the drops-primary economy reversal. Objective is GENUINELY met, more strongly than reported. Reproduced `npm run sim` (soft 6.39–6.52, hard 50.78–51.38, exit 0), `npm run test` 44/44, `npm run typecheck` clean, `npm run smoke` 4/4. Probed dropChance 0.8/0.6/0.3 with a throwaway copy of the sim: pacing genuinely collapses as drops thin (0.8 → 1/5 sweep seeds fail soft at 7.32 and 7/60 broad seeds fail, soft 2.24–8.40; 0.3 → hard 15.16 min with soft never reached on one seed), so drops are a real lever, not cosmetic. BUT the attribution ledger mislabels gold: `summarizeAttribution` computes `totalNet = dropNet + goldGross` and subtracts `resetLoss` from DROPS, so the printed/README "14.2% gold (net)" is actually gold GROSS. True net gold = goldGross − resetLoss = 0.000–0.049 on every seed (34 upgrades, 34 reset): every gold upgrade is wiped by the next equip. Real net drop share is ~100%; the 85.8% figure is conservative. Lesson: always recompute a "net" term from its own gross-minus-loss, and check which side of the ledger a cancellation is charged to. Also found: `loadGame` (state.ts) never recomputes the persisted `GearInstance.dps`/`clickDamage` cache, and `CURRENT_SAVE_VERSION` stayed 1 across a balance/formula change — an old-version-1 save loads with stale stats (probe: itemLevel-30 weapon loads dps=84 vs new-formula 2751). Self-heals only on the next equip/upgrade. The `dropGross` metric telescopes to the final item level, so the drops-primary gate is frequency-insensitive (passes even at dropChance 0.3) — it proves end-state dominance, not loot-stream behavior. Guards (SOFT_MAX_STAGE 40, HARD_MAX_STAGE 90, MAX_SOFT_AUTO_DPS 1e10, ±20% windows, canonical comfortable ranges, BOSS_TIMER_MS, HARD_WALL_PROJECTED_KILL_MS) were all verified byte-identical to HEAD; nothing loosened. /web/src unchanged and holds no balance numbers; engine-core still zero runtime deps and boundary-clean; SaveGame shape unchanged.
