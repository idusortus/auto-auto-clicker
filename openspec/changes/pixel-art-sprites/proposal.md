# Proposal

## Why

The whole point of the previous change was that the Expo host finally shows "theme pixel art and
animation" — but it doesn't, visually. Every one of the 32 theme asset slots ships as a
**generated placeholder blob**: a flat colour block with a corner marker and an index bar
(~5 distinct colours, 192–246 bytes each). Because the same enemy's idle / attack / hurt / death
frames are all near-identical blobs, swapping between them on a cue is **visually undetectable** —
so the arena reads as static coloured rectangles and players correctly report "there are no
animations, just blobs." The animation *code* works (event→cue mapping, frame swaps, flourishes,
tests), but it is animating art that has nothing to animate.

The theme art has been explicitly "deliberately not art" since T4; that placeholder strategy has
now outlived its purpose. This change replaces the placeholder blobs with **real old-school pixel
RPG sprites and true multi-frame animation**, so the existing cue framework finally reads as
animation.

## What Changes

- **Author real pixel art for the committed `fantasy` theme** — dependency-free, generated by a
  repo script (the successor to `make-placeholder-assets.ts`): a player character, a normal enemy,
  a boss enemy, the four Stray-Goblin ("Shiny") variants, and the spawn popup, in a coherent
  16-bit-era palette and readable silhouette, replacing the flat blocks.
- **Support real multi-frame animation sequences.** The theme currently declares exactly ONE image
  per action (`enemy-grunt-idle`, `…-attack`, `…-hurt`, `…-death`), so there is no way to express
  a looping idle bob, an attack wind-up→strike, or a multi-step death collapse. Extend the asset
  contract **additively** so each action maps to an ordered **frame sequence** with per-frame
  display timing, and render the sequence (looping for idle, one-shot for one-shot actions).
- **Animate the idle state and the action cues from the sequence.** The player/enemy/Shiny idle
  sprites loop their idle frames continuously; a cue (`playerAttack`, `enemyHit`/`bossHit`,
  `enemyDeath`/`bossDeath`, `shinySpawn`/`shinyClaim`, `stageEntered`) plays its sequence once,
  then the actor returns to its idle loop. Reduced motion keeps the first (rest) frame of each
  sequence — no looping, no motion — while informational text is unaffected.
- **Keep the declared-size / loud-failure contracts.** Every frame is a declared-dimension PNG;
  `npm run theme:check` still verifies file existence and exact pixel size; a missing frame fails
  loudly rather than rendering blank.
- **`lucky`** keeps the placeholder generator this change (explicitly out of scope), but its
  `assets`/`animation` sections are migrated to the new sequence shape so the theme contract stays
  uniform and both themes keep validating.

Explicitly **not** in scope: any gameplay/balance change, any change to the engine simulation or
save schema (stays **v4**), gear-icon art (the hosts don't render gear sprites), and full parity
with the web host's CSS transitions.

## Capabilities

### New Capabilities
<!-- None: the display/asset contract is owned by the engine's theme system and the host that renders it. -->

### Modified Capabilities
- `expo-host`: the "Theme-driven presentation" and "Theme animation cues drive transient sprite
  frames" requirements are strengthened — sprites are real multi-frame art (not placeholders), and
  animation cues play ordered frame sequences (looping idle) rather than swapping one static image.

## Impact

- **engine-core (theme display contract only):** `theme/types.ts` gains an ordered frame-sequence
  shape for asset slots; `theme/contract.ts` gains the frame-set declarations + validation
  (e.g. `ASSET_SLOTS` becomes frame-aware) and `validateAssetMeasurements` checks every frame;
  `theme/fantasy.ts` + `theme/lucky.ts` declare the new sequences; the generator
  (`make-placeholder-assets.ts`) is superseded for `fantasy` by a real-art generator. **No engine
  simulation, balance, RNG, or save-schema change** — the boundary/purity tests must stay green.
- **web host:** `renderer.ts` plays frame sequences for the idle loop and each cue (still
  `image-rendering: pixelated`, still reduced-motion gated); sprite CSS gains nothing identity-
  bearing.
- **mobile host:** `animation/` plays sequences (a per-actor frame ticker on top of the existing
  cue model); `ThemeImage` renders the current frame of a sequence; `useAnimationCues` returns a
  frame index/slot rather than a single slot.
- **Art/gates:** `theme:check` verifies every frame's exact size; the engine theme tests gain
  frame-sequence parity/shape assertions; `web`/`mobile` animation tests gain idle-loop and
  one-shot-sequence coverage.
- **Dependencies:** none added (art is generated dependency-free; animation reuses the existing
  Reanimated + timer seams).
